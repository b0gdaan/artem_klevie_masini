# Восстановление после сбоя

## Что гарантирует код

- Каждый файл пишется во временный файл в той же папке, затем атомарно переименовывается
  (`io_utils.atomic_write_bytes`). Полузаписанный результат под финальным именем не появляется.
- У каждого этапа в `runs/<run_id>/manifest.yaml` хранятся статус (`pending/running/succeeded/failed/interrupted`),
  номер попытки, время, отпечаток входов и хеши выходов.
- Этап пропускается при `resume` только если статус `succeeded`, отпечаток входов (код, конфиг, данные,
  окружение, выходы зависимостей) не изменился и все выходы на месте с теми же хешами.
- Перезапуск этапа переводит все зависимые этапы в `pending`; результат прошлой попытки не выдаётся за новый.
- `data/processed/<хеш данных>-<хеш кода>/PROVENANCE.json` хранит хеши файлов; повреждённый или чужой кэш
  пересобирается.

## Порядок действий

1. Посмотреть состояние:
   ```bash
   python -m research status --run-id latest
   ```
2. Продолжить:
   ```bash
   python -m research resume --run-id latest
   ```
   Команда сначала сравнивает текущие код, данные, конфиг и окружение с manifest и записывает изменения в
   `resume_history`. Затем пропускает проверенные этапы и выполняет остальные.
3. Проверить:
   ```bash
   python -m research verify --run-id latest
   ```
4. Если снимок данных изменился без нового `SHA256SUMS`, этап `ingest` падает. Изменять старый снимок нельзя:
   нужно создать новую папку в `data/raw/`, запечатать её (`checksums`) и сделать новый запуск.

## Долгие этапы

Сейчас самый долгий этап (bootstrap) занимает секунды, поэтому контрольные точки внутри этапа не нужны:
прерванный этап просто повторяется с тем же seed. Если появится долгое обучение, его состояние (параметры,
генераторы случайных чисел) нужно сохранять в `runs/<run_id>/checkpoints/` тем же атомарным способом.

## Проверено тестами

- прерывание на этапе `evaluate` и `resume` дают те же результаты, что непрерывный запуск;
- удалённый артефакт обнаруживается `verify` и восстанавливается `resume`;
- внедрённая ошибка даёт ненулевой код выхода, статус `failed` и отказ `release`;
- изменение одного числа в данных при том же размере файла меняет хеш и инвалидирует кэш.
